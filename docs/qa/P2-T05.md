# P2-T05 / TRIMR-48 — client discovery filters

TICKET: P2-T05. OWNER: Andrew. READY: yes. Native verification completed on 2026-11-21.

## Understood / done

Client discovery now exposes booking mode, an active category, an active saved
service address (including P1-T05's current-location confirmation flow), radius
and a requested Scheduled date/time. Shared native pickers and the existing
address UI are reused. The six local selections persist in the booking-draft
store. Config, server time, address rows/point, catalogue and results remain
TanStack Query data. Sign-out still clears the cache and draft.

A thin authenticated `get-discovery-filters` endpoint returns only scheduling
bounds, discovery radius, server time and an optional own active address point.
Every search obtains fresh inputs to catch aged times, config changes and
archived addresses. Invalid combinations show a reason and do not search. A
committed filter change clears the selected barber, invalidates prior discovery
without refetching its old inputs, and uses a new stable query key with no cursor.

There is no booking creation, result-card/map implementation or calendar promise.
Scheduled picker copy says requested. Domain calculations use elapsed minutes and
24-hour days with inclusive endpoints. GPS selection reuses a bounded sensor
helper and falls back to the same manual address form on denial/unavailability.

## Tests / limits

The API proof uses actual local JWTs: anonymous/invalid 401; barber/admin/unprofiled
403; malformed and foreign/missing/archived/unresolved-legacy address 422; forged identity ignored;
direct RPC denied to mobile roles and service RPC rechecks the stored client role.
Strict public-key allowlists and selected own point are asserted. Config changes
apply immediately; invalid config gives a safe 500, with no guessed fallback.

Migration replay preserves a pre-existing populated client profile and checks
service-only function privileges. No new tables or table RLS policy, money call,
state transition, scheduled worker or append-only-history mutation was added.
Test cleanup archives owned addresses, soft-deletes owned Auth fixtures and
restores config. No application reset, hosted deployment or provider call.

## Native verification

Environment: iPhone 17 / iOS 26.5, Expo Go SDK 57, local QuickTrimr. The current
bundle and existing local API were exercised through the UI with a synthetic
client. No customer credentials or customer data were used. No new location
permission was granted; the simulator already had permission and a synthetic
location. The temporary keep-awake process was stopped after testing.

Observed sequence:

1. Signed into the synthetic client; missing selections disabled search. Chose
   Available Now and an active Haircut category using the native menus.
2. Reused P1-T05's address picker. Its list correctly hid the initial unresolved
   legacy setup row. Searched a deliberately synthetic directory entry,
   confirmed it, named it QA confirmed home and saved through the real address
   endpoint. Discovery selected the newly saved ID automatically.
3. Entered a 2.5 km radius; a real search returned the empty-match state and
   retry/refresh actions. Navigated to Service addresses and Back with mode,
   category, address and radius retained.
4. Switched to Scheduled. The native date picker disabled past dates; selected
   22 November and changed the time from 11:54 am to 12:54 pm. Requested-time copy
   and a real Scheduled search were visible; no available/booked promise.
5. Used current location: the same P1 form loaded nearby synthetic suggestions.
   Confirmed one, saved QA GPS home and returned to Scheduled search with the
   requested timestamp and radius retained.
6. Temporarily changed only the local test lead bound from 240 to 1,800 minutes.
   Refresh rejected the existing requested time with derived **30 hours' notice**
   guidance and disabled search. The Try Available Now action switched mode and
   removed requested-time controls. This was a failure probe, not a product
   policy change; the approved 240-minute value was restored and verified.
7. Temporarily made that local config entry invalid and selected the other
   confirmed address. The screen showed the actual safe config error, with no
   hard-coded fallback or enabled search. After restoring 240, Try again recovered
   the same current filters and the real empty-match state.
8. Entered radius 0: inline field error and disabled search. Restored 2.5 and
   refreshed successfully. Scrolling kept required actions reachable; back,
   keyboard dismissal and both native pickers were exercised. Standard system
   text size was tested; large-text layout was not separately changed in native.

A setup-only IPv6/old-port connection problem was corrected by starting Metro on
IPv4 localhost. One existing Expo Go ExpoAsset startup error recovered on Reload;
no dependency or app permission change was required. These are not hidden app
fallbacks or unverified claims.

The new projection now mirrors the P1 picker by rejecting unresolved legacy
addresses. Its real API regression checks that rejection has the same envelope
as foreign, missing and archived rows; populated migration replay passes again.
The initial unresolved native setup row was archived; the two confirmed synthetic
