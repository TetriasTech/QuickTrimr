# P2-T05 / TRIMR-48 — client discovery filters

TICKET: P2-T05. OWNER: Andrew. READY: yes. Native verification pending.

## Understood / done

Client discovery now exposes booking mode, an active category, an active saved
service address (including P1-T05's current-location confirmation flow), radius
and a requested Scheduled date/time. Shared native pickers and the existing
address UI are reused. The six local selections persist in the booking-draft
store. Config, server time, address rows/point, catalogue and results remain
TanStack Query data. Sign-out still clears the cache and draft.

A thin authenticated `get-discovery-filters` endpoint returns only scheduling
bounds, discovery radius, server time and an optional own active address point.
Every search obtains fresh inputs to catch aged times, config changes and
archived addresses. Invalid combinations show a reason and do not search. A
committed filter change clears the selected barber, invalidates prior discovery
without refetching its old inputs, and uses a new stable query key with no cursor.

There is no booking creation, result-card/map implementation or calendar promise.
Scheduled picker copy says requested. Domain calculations use elapsed minutes and
24-hour days with inclusive endpoints. GPS selection reuses a bounded sensor
helper and falls back to the same manual address form on denial/unavailability.

## Tests / limits

The API proof uses actual local JWTs: anonymous/invalid 401; barber/admin/unprofiled
403; malformed and foreign/missing/archived address 422; forged identity ignored;
direct RPC denied to mobile roles and service RPC rechecks the stored client role.
Strict public-key allowlists and selected own point are asserted. Config changes
apply immediately; invalid config gives a safe 500, with no guessed fallback.

Migration replay preserves a pre-existing populated client profile and checks
service-only function privileges. No new tables or table RLS policy, money call,
state transition, scheduled worker or append-only-history mutation was added.
Test cleanup archives owned addresses, soft-deletes owned Auth fixtures and
restores config. No application reset, hosted deployment or provider call.
