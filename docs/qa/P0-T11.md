## Understood

Add the KB's baseline client/barber ownership reads and admin operational reads, backed by a
verified-JWT identity and database role lookup. Preserve deny-all writes and immutable evidence,
separate public/safe projections from private tables, and prove the boundary at the real API.
This is a database-access foundation, not auth UI, discovery, booking/payment actions or admin UI.

## Done

- New immutable-after-merge migration `20261008000000_baseline_rls.sql`: all 21 tables retain
  RLS; 32 SELECT-only policies, all gated by `private.current_user_role()` from `profiles`.
  The stable, no-argument definer has an empty search path, qualified references and trusted
  owner; it cannot be called as a public PostgREST RPC or accept another user's ID.
- Explicit current-column SELECT grants prevent future private columns becoming readable
  automatically. Anonymous reads are denied. Existing application DML grants plus absent write
  policies prove actual RLS denial, including own rows/admins, not a UI or missing-write-grant no-op.
- Read-only security-barrier owner-rights views: ID-only `public_barber_profiles` and seven-field
  own-booking `client_payments`. Clients cannot read the base payments table; caller predicates
  and explicit fields constrain the intentional owner-rights bypass.
- Shared local Auth/HTTP/raw-response helpers with fixed origin, no redirects, serialized bodies
  and privacy-safe failure messages. Three credential-free regression tests. Adapted the core
  verifier rather than leaving its historical deny-all reads failing after policies land.
- Preserved schema/enum/cents/geography/FK/concurrency/append-only checks. Replay now hashes
  grants too; it no longer suppresses privilege statements.
- [RLS access contract](../architecture/baseline-rls.md), current workflow/setup docs, backlog
  scope/contracts/tests and downstream sync notes. No KB business rule or dependency changed.

## Drift

- Added the missing contract examples before implementation. Clarified KB-required server-owned
  writes: no baseline write policy, even for admin. Existing append-only triggers are retained,
  not replaced by absence of a client policy alone.
- Column-level privacy requires explicit grants/projections, not clients selecting fewer fields.
  Only existing ID data is public at this stage; no name/photo/Connect-ready discovery is invented.
  Payments are published only in the explicit own-client safe view. Feature columns remain private
  until their owning migration deliberately publishes them.
- Adapted the previous deny-all verifier to the current policies and extracted reusable Auth/HTTP
  helpers. Strengthened replay to include grants rather than hashing definitions alone.
- Two verifier defects were found and corrected: a hidden-RPC probe sent an unserialized object
  (malformed `400` / `PGRST102`, not valid denial evidence); a newly added HEAD counter was first
  scoped to the wrong function. Final serialization/scope fixes preserve the original assertions,
  and the complete suite passes. No policy/permission was loosened to make a test pass.
- No KB stable ID changed and no new business decision was made. Checked all eight affected
  tickets: P0-T12 uses privileged local seed SQL; P1-T01/P1-T03 keep server-created profiles;
