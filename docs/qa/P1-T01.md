# P1-T01 · Client and barber authentication

Andrew owns [TRIMR-31](https://tetrias-tech.atlassian.net/browse/TRIMR-31). All five dependencies were Done before implementation. The mobile routes use the server-owned role and onboarding state from `P1-T03`.

## Verification

| Acceptance criterion | Evidence |
| --- | --- |
| Email signup, confirmation, sign-in, and sign-out for both roles | `node apps/mobile/test/verify-auth-live.mjs` against local Supabase and Mailpit. iPhone 17 also exercised sign-in and sign-out with disposable client and barber accounts. |
| Secure session survives restart | Signed in as a disposable barber, terminated the Expo Go process with `xcrun simctl terminate`, and reopened QuickTrimr. It returned to Barber journey without entering credentials. The native client uses Expo SecureStore. |
| Client, barber, and incomplete onboarding routing | Live test asserts all three routes from real Edge Function responses. The simulator reached the incomplete client onboarding screen and completed Barber journey. |
| Wrong password and unknown email are indistinguishable | The live test compared the Supabase status, error code, and normalized app error. The iPhone displayed “The email or password is incorrect.” |
| Repeated attempts are throttled and handled safely | Local GoTrue v2.188.1 returned 429 on attempt 31 in an isolated loopback test with a fixed trusted test-client header. `auth-errors.test.mjs` checks the 429 message. The stock Supabase CLI stack did not throttle this test because it had no rate-limit header configured. |
| Password recovery works | The live test requested a Mailpit code, verified it in a separate session, changed the disposable account's password, and proved that only the new password worked. |
| Cold-start loading and no signed-out route during session restore | The root waits for Supabase's initial session event and profile sync before mounting the session-dependent navigator. The signed-in iPhone reopened to the same journey. |
| No auth secrets in mobile | `pnpm check:client-env` and iOS and Android Expo bundle exports. The app reads only the public Supabase URL and anon credential. |
| Admin self-assignment denied server-side | `node scripts/db/verify-profile-sync.mjs` asserts HTTP 403 and zero writes. The mobile live test also changes a fixture's signup metadata to `admin` and confirms its stored role still controls routing. |

The live tests leave disposable users in the local database. Hosted email confirmation, template delivery, and password-grant rate limiting still require verification on QuickTrimr's hosted development project. See the [mobile setup instructions](../../apps/mobile/README.md). The simulator checks used iOS, and Android was checked by a bundle export.
