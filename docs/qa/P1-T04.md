## Evidence

Run `node scripts/db/verify-client-profile.mjs` from the repository root with local QuickTrimr
Supabase migrated and `pnpm functions:serve` running. The verifier uses disposable local users.

| Acceptance criterion | Result |
| --- | --- |
| Save the profile and gate the client journey on an active address | iPhone 17 showed [Profile saved](P1-T04/profile-saved.png) after the first save. A repeat save with a disposable owned active address opened the client journey. The live verifier proves foreign and archived addresses cannot unlock it. |
| Enforce required fields | [The iPhone form](P1-T04/required-fields.png) showed errors on both empty fields. The verifier called the function directly and received field-level 422 errors. |
| Reuse one React Hook Form and Zod contract across app and function | The form uses `zodResolver(completeClientProfileRequestSchema)`. The Edge Function parses the same shape before calling its RPC. `node scripts/api/contracts.mjs --check` confirmed the generated documentation. |
| Validate and normalize Australian mobile numbers | `node --test packages/validation/test/client-profile.test.mjs` covers domestic, international, wrong length, landline and unsupported prefix inputs. The raw database read and iPhone edit view confirmed `+61` format. |
| Resume after closing the app | Entered a name and formatted number, chose a synthetic image, terminated and relaunched Expo Go. The iPhone restored all three unsaved selections. |
| Preserve verification state | The live verifier checks `not_started` in the exact server response for first save, retries and address-gated completion, and rejects a client-supplied verification value. |
| Keep entries on failure and show pending state | The iPhone presented the photo picker with the in-progress controls disabled. A controlled role denial on the disposable fixture made save fail without losing either field or the photo. Restoring its role allowed the same form to save. |

The optional photo test exercised the picker, upload and stored association on iPhone. The live
verifier denies foreign, anonymous and public reads, cross-client writes and uploads by a barber.
The migration retains the profile row policies, grants only the new contact and photo-reference
columns, and uses a private, owner-scoped Storage bucket. It introduces no new table.

Eighteen parallel first saves across three users produced one save audit entry per user. The audit
entries contain the two state flags and no contact details. Direct authenticated profile RPC calls
were denied. The server derives the target profile from the verified session.

## Drift and audit

`RULE-ONBOARD-02` and the existing executable API contract require an active address for full
onboarding. The backlog now reflects this. P1-T05 owns the address entry UI and the recheck after
address changes. P2-T08 continues to require a complete profile and owned address, and P5-T02
retains the private admin access boundary. No knowledge-base rule changed.

The code audit covered schema and RLS, private Storage, the Edge Function, the mobile form and
draft, and the tests. The live role-denial test found a collision with PostgreSQL's `current_role`
identifier. The variable was renamed. The migration also grants the archive marker under the
existing row policy so the earlier own-address read remains compatible. Local test fixtures remain in
the local database. Hosted deployment and Android device runtime checks are outside this run.
