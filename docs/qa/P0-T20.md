## Reproduce the checks

1. Use the matching file and variable in the [environment contract](../architecture/environment-variables.md#google-key-restrictions).
   In Android Studio or Gradle, run `:app:signingReport` for the actual build variant. Check the
   APK with `apksigner verify --print-certs <probe.apk>` before comparing its SHA-1 with the saved
   restriction. If you use a different development signer, register its real fingerprint before
   testing its build.
2. Use the [Android Maps sample](https://developers.google.com/maps/documentation/android-sdk/start)
   and [iOS Maps sample](https://developers.google.com/maps/documentation/ios-sdk/examples) to
   render a map at a public landmark. Repeat with an unapproved package or bundle ID holding the
   same key. For the [JavaScript map](https://developers.google.com/maps/documentation/javascript/adding-a-google-map),
   load the same local page in fresh contexts at ports 3000 and 3001.
3. From a local Edge Function, read `GOOGLE_MAPS_SERVER_API_KEY` and call
   [Places Autocomplete (New)](https://developers.google.com/maps/documentation/places/web-service/place-autocomplete)
   and [Routes Compute Routes](https://developers.google.com/maps/documentation/routes/compute_route_directions)
   using the API key header. Use a public landmark as the Places input and two public points as the
   route. Count a result only when the response succeeds and contains a prediction or route.
   Preserve the status and result category without raw request headers or payloads.
4. Run `pnpm check:client-env` and `pnpm --filter @quicktrimr/mobile build`. Build the admin app
   with `pnpm --filter @quicktrimr/admin exec next build --webpack`.
   Read the backend key directly from the ignored Supabase env in a local process. Feed it via
   standard input to `rg --fixed-strings --quiet -f -` with binary files, hidden files and ignored
   build paths included. Verify no match in `apps/mobile/dist/android`,
   `apps/mobile/dist/ios` or `apps/admin/.next/static`. Report only pass or fail.
5. In the customer billing account, reopen the saved budget. A Cloud Shell readback can use
   `gcloud billing budgets describe` and `gcloud beta monitoring channels describe` to compare
   the stored filter, amount, rules and linked channel. Compare the project number with
   `gcloud projects describe quicktrimr-dev --format='value(projectNumber)'`.
   The project-specific scope was applied via the Cloud Billing Budget API after the Console
   project picker offered only all projects. [Google CLI reference](https://docs.cloud.google.com/sdk/gcloud/reference/billing/budgets/create)
