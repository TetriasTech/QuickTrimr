26 November 2026. [TRIMR-58](https://tetrias-tech.atlassian.net/browse/TRIMR-58).

The ten-second primary and thirty-second reconciliation jobs process
persisted deadlines through the same conditional database transition.
Postgres locks the barber profile before the request, then rechecks both
state and time. Available Now misses, receipts and request audits commit
with expiry. The authenticated client reads the resulting status through
the existing projection.

## Audit and traceability

Audited the conditional transition, service-only API and RPC, shared worker
transport, grants and RLS, bounded due scan, cron installation, separate
monitor and verification scripts. The test exercised role denial and all
four Data API verbs on the private run table. The operation is database-local,
uses the existing deadline comparator and source-session receipt and writes
only an expiry audit for the request. Booking status history records accepted
bookings and has no row to append for a request that expires. The monitor
sends only a worker name, health status and finite alert reasons.

No unresolved Critical, Major or Minor findings. The KB gates now resolve
to `CFG-REQUEST-EXPIRY-WORKER-OPERATIONS` and
`RULE-OPS-REQUEST-EXPIRY-VERIFICATION`. P0-D07, P2-T03 and P2-T08 keep their
contracts. P3-T06 consumes the durable expiry audit and owns payment
authorisation release. P4-T01 can continue using the existing status
projection. Generated backlog indexes remain managed on main.
