## UNDERSTOOD

A client can open a barber profile before requesting a booking. The read must expose only the P1-T06 public projection, current active services and integer-cent prices, an approximate public area, and an honest empty review state. Search, request submission and review listing remain their owning tickets.

## DONE

- Client route `/barbers/[barberId]`, with optional `serviceCategoryId` selection, a native title/Back destination, signed photo or initials, biography, experience, area, prices and reviews placeholder.
- One client request to `get-public-barber-profile`. Verified JWT identity and the stored client role precede data access; the service-only RPC independently rechecks the client role and the target's current Connect gate. Unknown, incomplete or ineligible targets return `profile: null`.
- The SQL consumes `private.barber_public_profiles`. Raw profile/service-table RLS, reference-area privacy and the foundation's ID-only view remain intact. The photo identifier is internal; only the configured expiring signed link crosses the Edge boundary.
- Active barber services joined to active categories, catalogue order, 20-row keyset pages and one continuation probe. No platform price, route-supplied amount or historical booking rewrite.
- Shared public identity/area/photo/rating schema reused by the future discovery response. Existing owner/public photo reads share the same signer and expiry config.
- Fixture-driven rendering tests import P0-T08's typed fixture entry explicitly. Production routes have no fixture import or failure fallback.
- Fixed a shared money formatter crash exposed by Hermes: integer arithmetic and decimal grouping preserve every cent without `Intl.NumberFormat(BigInt)`.
