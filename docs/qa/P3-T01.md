# P3-T01 · Payment authorisation

[TRIMR-60](https://tetrias-tech.atlassian.net/browse/TRIMR-60) · Andrew · 27 November 2026

QuickTrimr creates one manual-capture PaymentIntent for a pending request. Its amount and
commission split come from the immutable request snapshot. Stripe PaymentSheet collects the
card and handles 3D Secure. The server reads Stripe before recording the authorisation and
its deadline. The test screen runs in native development builds with a Stripe test publishable
key. TRIMR-65 will connect the flow to booking submission.

The live verifier exercises unauthenticated, non-client and cross-client requests, invalid UUIDs,
direct RPC permission, direct reads of the provider ID, and attempts to write payment status.
The migration extends the existing RLS-protected `payments` table. The new service-only RPC
commits each change before any provider call. Existing booking and request statuses are unchanged
by this slice, so booking history remains the responsibility of their respective transitions.

## iPhone verification

On iPhone 17 (iOS 26.5), the empty verification state prompted for a card. Continue showed a busy
state and opened Stripe PaymentSheet. A synthetic card opened Stripe's 3D Secure test challenge.
Completing it returned to QuickTrimr, which showed **Card authorised** and **A$45.03**. Stripe
reported `requires_capture` with zero captured cents. The local payment row reported `authorised`
and 4,503 cents. The test holds were released and the test client was signed out and soft-deleted.

## Reproduce

Start and migrate the local stack, then serve the Edge Functions with the existing Quick Trimr
sandbox configuration. Use the Stripe sandbox only. The verifier generates disposable users and
test PaymentIntents and releases its test holds when it finishes.

```sh
pnpm db:start
pnpm db:migrate
pnpm functions:serve --env-file supabase/.env.local
node --env-file=supabase/.env.local scripts/stripe/verify-request-authorisation.mjs
node --test supabase/functions/create-payment-authorisation/test/handler.test.mjs
```

The iPhone uses `EXPO_PUBLIC_STRIPE_PUBLISHABLE_KEY` from the matching sandbox. Open
`quicktrimr://sandbox-payment/<synthetic-request-id>` as the owning test client in an iOS
development build. Use the provider's [3D Secure test card](https://docs.stripe.com/testing#regulatory-cards).
The amount and the resulting status can be verified independently in Stripe and the local database.
