## Delivered slice

Google Maps in the development clients shows the selected service-address pin and
one shared public SAL marker per loaded matching area. Counts represent loaded,
deduplicated pages. Area taps reuse the existing virtualized result cards and their
profile navigation; neither geographic filtering nor a second card renderer was
introduced. Pages are loaded explicitly while using the map or area selection.

The pure `discoveryMapAreas` function copies only SAL IDs, labels, public points and
counts. It fails closed on inconsistent points. Search retains its strict DTO and
opaque cursor. `get-discovery-filters` adds only the public map refresh cadence,
read from `private.platform_config` by migration
`20261122010000_discovery_map_policy.sql`. No table or RLS policy was added.

Completed gestures use a monotonic, one-at-a-time scheduler with a coalesced trailing
refresh and live config updates. Camera fitting is not a search. A refresh restarts
the cursor chain without changing the selected address/radius. Background updates
keep the map visible without refresh spinners. Initial loading, explicit pagination
progress, actionable errors and empty guidance remain visible.

## Reproduce

Use the normal local stack (`http://127.0.0.1:55321`, database container
`supabase_db_quicktrimr`) and the discovery functions environment. Do not reset the
database: it contains the imported Australian address dataset.

```bash
pnpm db:migrate
pnpm functions:serve --env-file supabase/.env.discovery.local
node scripts/db/verify-discovery-filters.mjs
node scripts/db/verify-discovery-map.mjs
# Keep the same disposable supply for native QA, then send cleanup on stdin:
node scripts/db/verify-discovery-map.mjs --hold
```

The map proof uses explicit synthetic eligibility facts, two local barbers and a
disposable category; it makes no Stripe calls. Credentials stay in memory.
Cleanup archives the category/services, disables sessions and soft-deletes the
synthetic logins, preserving audit attribution and the public SAL dataset.
The held fixture run completed cleanup after its timeout; no fixture credentials
were saved. The native screenshots contain synthetic data only.

The config API proof rejects missing/invalid JWTs, barber/admin/unprofiled roles,
malformed input and direct mobile RPC access. Forged identity does not override
JWT identity. Foreign/missing/archived/unresolved addresses get identical field
errors. It changes the map interval from 2,000 to 3,500 in the database, proves the
next response changes, checks invalid values fail closed, and restores all config.
See [API isolation evidence](evidence/P2-T07/api.json).
