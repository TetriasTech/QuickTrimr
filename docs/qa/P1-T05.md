# P1-T05 · Client address management

TRIMR-35 · Andrew · Local Supabase and iPhone 17 simulator, iOS 26.5.

## Reproduce

Apply the migration before loading G-NAF. Use the official November 2026 **GDA94** Standard ZIP. Check its SHA-256 before importing. The importer uses the fixed local QuickTrimr Docker container and prints the release and archive hash.

```sh
pnpm db:start
pnpm db:migrate
shasum -a 256 /path/to/g-naf_nov26_allstates_gda94_psv_120.zip
node scripts/db/import-gnaf.mjs /path/to/g-naf_nov26_allstates_gda94_psv_120.zip
```

The archive used for verification had SHA-256 `2956087be73dd5b72b62ca45b6f07edc378da04b08daa9c663d0e64ba33aa740`. The full import processes ACT, NSW, NT, Other Territories, QLD, SA, TAS, VIC and WA. Append `--local-states ACT` for the local API smoke test. The import excludes locality-only and street-extent geocodes. It stages data in a private schema, commits batches of 25,000, and removes retired IDs only after the selected jurisdiction has fully published. Rerun the same release to complete an interrupted import. The migration creates an empty directory. Provisioning data in a hosted environment is a separate deployment step.

[Official G-NAF release](https://data.gov.au/data/dataset/19432f89-dc3a-4ef3-b943-5326ef1dbecc/resource/340dfee4-027d-411d-acdf-4944b102ede7) · [Open G-NAF User Licence](https://www.data.gov.au/data/dataset/19432f89-dc3a-4ef3-b943-5326ef1dbecc/resource/09f74802-08b1-4214-a6ea-3591b2753d30/download/20160226-eula-open-g-naf.pdf).

## Acceptance evidence

| Criterion                          | Observed result                                                                                                                                                                  |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| List, add, edit and archive        | iPhone exercised all four actions. The live API checked the saved list, updated access notes and archived the same address. See [saved address](P1-T05/saved-address.png).          |
| Address gates onboarding           | Saving the first address after profile basics opened the client journey. Archiving the only address returned the iPhone to the first-address prompt. API assertions cover both.   |
| Saved point and field-level error  | The API checked that a valid manual save persisted a PostGIS point. Unresolved and ambiguous typed entries returned a `422` on `line1`. Explicitly selecting a match succeeded.    |
| Australian search and manual entry | The API checked both paths using the same public G-NAF landmark. The iPhone also selected a suggestion and saw the postal fields fill. See [autocomplete](P1-T05/autocomplete.png). |
| Location consent and fallback      | After Allow Once, a simulator location near the landmark returned eight candidates for confirmation. After denial, manual entry saved the landmark and completed onboarding.       |
| Archived record and active list    | The active list excluded the archive. An owner-only raw read found the original ID and unchanged point, so archive preserves the row for future references.                         |
| Archived edit                      | Editing the archived address returned `409 address_archived` with the expected raw body.                                                                                          |
| Idempotent archive                 | Six concurrent archives returned the same timestamp and produced one append-only audit event. Six concurrent identical creates returned the same address ID.                       |
| Cross-client denial                | Raw API reads from another client and an unrelated barber revealed no row. Cross-client update and archive returned the same generic `404` as a missing address.                   |
| No delete path                     | Direct REST `DELETE` returned `403`, as did direct `PATCH` and `POST`. The Edge contract exposes archive only.                                                                     |
| Private lookup                     | Wrong-role lookup returned `403`. Direct mobile directory and RPC calls failed. Raw lookup responses expose postal candidates without coordinates or account information.             |
| Loading, errors and empty states   | The simulator showed the empty first-address prompt, lookup loading and the [location denial fallback](P1-T05/location-denied.png). API checks exercised the field error contract.  |

The existing `client_addresses` owner policy remains active. `private.address_directory` has RLS and no mobile access. Writes derive identity from the verified JWT. Parallel writes share the existing client-profile lock with onboarding. Address audit rows contain completion flags and omit the address, coordinates and access notes.

## Audit and remaining verification

- The manual match now rejects tied best-ranked results at distinct points. This prevents a silent selection at the wrong location.
- The import publishes in bounded batches after a jurisdiction-sized transaction exceeded local Docker memory. Exact lookup, autocomplete and nearby queries have separate indexes.
- `EXPLAIN` on the local nearby query used `address_directory_point_idx` to order by distance and return the first eight street-level candidates.
- Android and iOS exports passed. The running flow was exercised on iPhone. Android runtime and a hosted import were outside the local proof.
- P2-T08 owns booking address snapshots and P4-T03 owns barber-facing disclosure. This ticket verifies the retained address row and its active-list exclusion.
