# P1-T02 · Admin authentication and route guard

Andrew owns [TRIMR-32](https://tetrias-tech.atlassian.net/browse/TRIMR-32). `TRIMR-20` and
`TRIMR-25` were Done before implementation. Andrew approved `CFG-ADMIN-SESSION-HOURS` as eight
hours from sign-in. The resolved decision remains in the knowledge base under
`TBC-ADMIN-SESSION-LIFETIME`.

## Local evidence

Run `node scripts/db/verify-admin-auth-live.mjs` with the local QuickTrimr database migrated
and Playwright Chromium installed. The script builds and serves the app on `127.0.0.1:3102`
and creates disposable users against `127.0.0.1:55321`.

| Acceptance criterion | Evidence |
| --- | --- |
| Admin can sign in and sign out | Chromium submitted both forms, reached the dashboard with the expected identity, and returned to `/login`. Only HttpOnly, Secure, SameSite=Lax cookies carried the Auth session. |
| Client and barber requests cannot reach admin pages or receive operational content | Raw HTML and RSC requests with each account's valid session returned HTTP 403 and no protected markup. Unknown email and valid non-admin credentials produced the same form error. |
| Role is resolved from the database on every request | Signed Auth metadata claiming admin did not override either non-admin database role. Changing a disposable admin's role immediately denied the previously authorised cookie. |
| Layout and server entry points share the guard | Layout and page call `requireAdmin()` before rendering. Unit tests verify both are denied and the page waits for verification. Proxy returns the public denial before streaming. |
| Sign-in and sign-out create immutable audit entries | Browser flow recorded one `admin.sign_in` and one `admin.sign_out` for the session. Three rounds of parallel open and close calls recorded exactly the same counts per session. A closed session could not reopen. |
| Eight-hour hard deadline and expired redirect | The test read eight hours from private config and aged a disposable session. A request just before expiry succeeded. A refreshed token after expiry still returned HTTP 302 to `/login?reason=expired` for HTML and RSC. Fresh sign-in restored access. |
| Anonymous and invalid sessions fail closed | Requests without a session received HTTP 302 to `/login`. A malformed session cookie redirected to the expired-session path. A previously signed-out cookie could not restore access. |

Configuration is migration-managed. The test confirms RLS on the private config table, denies application roles table privileges, and verifies the table cannot be read through PostgREST.

## Drift and audit

The backlog now cites the approved expiry value. The 403 outcome serves the forbidden page directly. Rewriting to that page produced inconsistent HTTP status codes in real HTML and RSC requests. All nine downstream Phase 5 tickets keep their existing dependencies and use the guard at each protected page, loader and action boundary.

The audit covered the migration, authorization, cookies, server actions, routes and tests. The incorrect forbidden response status was fixed and retested. Hosted migration and verification are pending. Local test accounts and their audit evidence remain in the local database.
