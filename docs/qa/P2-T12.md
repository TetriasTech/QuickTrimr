# P2-T12 / TRIMR-55 — Accept booking request

**Owner** Andrew. **Ready** Yes. All seven prerequisites are Done. Andrew approved
Option A for the closure policy on 26 November 2026. The KB records the decision
under `RULE-AVAIL-07` and resolves `TBC-AVAIL-ACCEPTANCE-BULK-CLOSURE`.

`POST /functions/v1/accept-booking-request` takes a request ID and uses the
verified barber's identity. The Edge Function checks the persisted role and
delegates to a service-only RPC. The RPC takes the barber profile lock, then
the request lock. It checks the real server clock after the lock wait, reads
current reliability and checks the Available Now job slot with the shared
`P2-T11` predicate. A conditional request update and a unique booking index
prevent duplicate acceptance. A booking conflict rolls back the request update.

The booked service and integer-cent amounts come from the immutable request
snapshot. The new booking starts at `accepted_pending_payment`. History has
a null previous booking status because this is the first booking row. An
Available Now acceptance invokes the `P2-T03` session transition and closes
eligible siblings in the same transaction. Each sibling audit row includes the
accepted request ID and the resulting terminal status. This provides a durable
reference for the later payment and notification consumers.
