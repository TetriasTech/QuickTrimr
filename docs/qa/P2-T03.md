# P2-T03 / TRIMR-46 — Available Now auto-disable rules

Owner: Andrew. Ready: yes. Branch: `codex/trimr-46`.

## Understood

Deliver one server-owned availability transition module: elapsed deadlines expire,
consecutive unanswered requests auto-disable, responses reset misses, acceptance
makes current availability busy, and manual stop remains distinct. Effects are
atomic, idempotent and audited. Misses/declines never create reliability offences.
The slice also owns bounded scheduling, recovery, private permissions, independent
monitoring, retention and measured hosted evidence.

## Done

- Pure domain policies and parity-tested atomic SQL transitions, using the existing
  profile-before-child lock order and server clock after lock acquisition.
- Immutable per-request receipts and a nullable source-session reference for future
  request producers. No request-creation/acceptance/decline/expiry handler was built.
- The existing manual-stop API now uses the shared transition, retaining its
  `available_now.stopped` audit action and idempotent response.
- A reference-only, JWT-verified worker endpoint delegates authorization to the
  service-only SQL RPC; client/admin/forged metadata cannot grant worker access.
- Two fixed pg_cron schedules: bounded indexed expiry every ten seconds and minute
  health checks. Advisory locks prevent overlapping sweeps; interrupted database
  transactions release claims without persisting partial effects or audits.
- Private RLS-protected state, run/failure records and monitoring delivery records.
  Errors record SQLSTATE only. No user, request, booking, address or contact data is
  sent to monitoring. pg_net transmits after commit, outside database locks.
- A code-managed Sentry Cron monitor in `development`, with a one-minute schedule,
  one-minute missing-check-in margin, and first-failure / first-recovery handling.
  The project alert is limited by `monitor.slug` and emails the approved recipient.
- Versioned operational install and target-guarded local/hosted operator scripts.
  The original local G-NAF dataset, other project stacks and immutable audits remain.


Run hosted database CLI operations sequentially. The monitor proof injects faults
only into the pinned isolated test environment and restores both schedules in its
cleanup. It intentionally sends the operational test alerts Andrew approved.
The DSN must already exist in the ignored backend environment; never paste it into
a command or commit it. See [the operational runbook](../operations/available-now-worker.md).

New tables: `private.available_now_request_receipts`, `available_now_worker_state`,
`available_now_worker_runs`, `available_now_worker_failures`,
`available_now_monitor_deliveries`. Every table enables RLS and revokes runtime
access. Real API tests cover every CRUD verb for anonymous, both clients, both
barbers, admin and service-role callers. Existing owner-only session reads are
preserved and cross-owner reads return no rows. Managed Cron retains its native
RLS. Provider-owned Net/Vault tables retain provider defaults; their schemas are
explicitly excluded from the Data API, proven by `406/PGRST106` on actual objects.
Their ownership or protected implementation-function permissions were not changed.

No money or booking status transition is introduced, so Stripe/capture/refund,
integer-cent snapshots and `booking_status_history` tests are N/A for this slice.
Future request handlers must use the documented private hook in the same transaction
as their own terminal transition. Their integration is explicitly outside P2-T03.

## Audit

Scope: P2-T03 domain policy, SQL/RLS, worker/monitor operations, Edge handler,
API/native proofs and changed consumer contracts, against QUICKTRIMR_AUDIT_PROMPT
A–F. The final A–F review checked authorization/RLS, privacy, pure-policy parity, config sources, parent/child lock ordering, request receipts, audit immutability, bounded indexed work, failure acknowledgements, after-commit I/O, native state rendering and phase boundaries. No further findings.

Findings already resolved during delivery:

- Major, E/F: byte-comparing service JWTs rejected a legitimately authorized hosted
  server credential. Delegating verification to the service-only PostgREST RPC
  fixes the issue; real user/admin denials and parallel server calls pass.
- Major, F: the baseline statement-start timestamp could understate transition
  lateness after a lock wait. The session-specific clock trigger fixes this; final
  local/hosted measurements were repeated afterward.
- Major, F: a nonzero process exit was insufficient proof of SQL privilege denial.
  PostgreSQL 17.6 on this Mac crashed on the forbidden direct private-function probe
  under `SET ROLE authenticated`. Exact catalog ACL assertions replace that unsafe
  probe, alongside the actual API denial checks. The completed scratch proof now
  passes and cleans up successfully. Cleanup also preserves an original proof error
  instead of masking it with a second error.
- Minor, E: the local PostgreSQL 17.6 direct-SQL denial-probe crash is a platform
  limitation to revisit during a safe local database upgrade. No runtime role can
  access this private RPC/schema through the API, and no permission was widened.
  The existing database was not reset or upgraded as part of this ticket.
